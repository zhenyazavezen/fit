# DECISIONS — принятые решения по ZAVEZEN_FIT

Формат: что решили, почему, что из этого следует. Статус: **принято** (подтверждено владельцем) или **предложено** (ждёт согласования).
Последнее обновление: 2026-11-12 (вечер).

## Принято

### D-001. Никаких визуальных демонстраций упражнений
Не используем фото, видео, GIF, 3D-манекен, виртуального тренера и любые другие показы движений. Это продуктовое решение, а не временное ограничение. Подача — типографика, крупное время, индикаторы этапов, текстовая инструкция.
Следствие: в схеме данных нет полей `demo`/`video`/`image`. Валидатор данных должен падать, если такое поле появится. Вернуть визуальный показ можно только по отдельному согласованию.

### D-002. Голос тренера и озвучка не используются
Голосовые режимы и озвучку упражнений не делаем. Оставляем короткие звуковые сигналы (WebAudio) и вибрацию, обе настройки можно выключить.

### D-003. Карта мышц отложена
Целевые и второстепенные мышцы показываются текстом (названия и чипы). К визуальной карте можно вернуться позже.

### D-004. Без аналитики
Трекеры и аналитику не подключаем. Любая аналитика потребует отдельного согласования и согласия пользователя.

### D-005. Стек: React + TypeScript + Vite, статический frontend
Выбор владельца. Плюсы: типы, компоненты, тесты. Цена: появляется шаг сборки, растёт размер загрузки (React), основа, написанная на ванильном JS, переносится.
Условия: минимум зависимостей (в рантайме только `react` и `react-dom`), результат — статические файлы для бесплатного хостинга (GitHub Pages / Cloudflare Pages). Бюджет начальной загрузки задаётся и проверяется в CI (значение утвердим после первой сборки).

### D-006. Backend, PostgreSQL, Workers и платные сервисы пока не подключаются
Всё работает на устройстве. Серверные части (проверка Telegram initData, хранение, подписка через Telegram Stars) закладываются интерфейсами, без реализации. Оплату не делаем до завершения базовой версии и согласования архитектуры.

### D-007. Русский и украинский, локализация в отдельных файлах
Строки интерфейса: `src/i18n/locales/{ru,uk}.json`. Контент каталога: `src/data/content/{ru,uk}.json`. Структура данных (`exercises.json`, `programs.json`) от языка не зависит. Отсутствующий перевод падает на русский; проверка полноты — скриптом.

### D-008. Черновой каталог (40 упражнений, 9 программ) сохраняем как черновик
Тексты написаны по общим знаниям и **не прошли профессиональную проверку**. Каждая запись получает `review: "draft"`. Нельзя выдавать их за проверенную методику. Противопоказания и ограничения добавляются только при достоверном основании (источник указывается в данных). Общее уведомление «не медицинская рекомендация, при боли и дискомфорте прекратите» показывается в приложении. Обещаний результата («сжигает жир», «лечит», «безопасно для всех») в текстах быть не должно.

### D-009. Данные пользователя не доверяются frontend'у
Telegram `initDataUnsafe` используется только для показа имени. Проверка подписи initData и любые решения о доступе — только на сервере (в будущем).

### D-011. Принципы переноса существующих модулей
Не переписывать механически: переносим то, что работает (хранилище с защитой данных, Telegram-интеграция, математика дат, i18n-ядро, звуковые сигналы), адаптируем то, что завязано на DOM (роутер, util, загрузка i18n). План — `docs/MIGRATION.md`.

### D-012. Роутер — React Router
Выбор владельца (вместо собственного роутера). Условия: не использовать hash-маршрутизацию (hash занят параметрами запуска Telegram `#tgWebAppData`); системная «Назад» и Telegram BackButton должны работать через общий стек обработчиков (шторки и подтверждения перехватывают «Назад»). Логика из `router.js` переносится как слой поверх React Router (`useBackGuard`, синхронизация BackButton, восстановление прокрутки). Вариант маршрутизатора (memory/browser с `basename`) выбираем при настройке и проверяем e2e на GitHub Pages и в Telegram.

### D-013. Стили — CSS Modules с централизованными токенами
Токены дизайн-системы — в одном файле `src/styles/tokens.css` (CSS-переменные). Компоненты используют только токены, значения «в лоб» запрещены. Tailwind и UI-киты не используем.

### D-014. Шрифт Manrope — локально
WOFF2-файлы лежат в `public/fonts` (кириллица и латиница), подключаются через `@font-face` с `font-display: swap`. Рядом сохраняется текст лицензии (SIL OFL 1.1) и указание автора. Внешних запросов к Google Fonts нет. Файлы нужно получить из официального источника; из текущей среды скачать их нельзя (сеть закрыта).

### D-015. Цель «Снижение веса» остаётся
В описании цели и программ нет обещания похудения за счёт одних тренировок. Обязательный текст-пояснение: вес зависит не только от тренировок (питание, сон, общая активность), результат не гарантируется. Программы в этой цели помечаются нейтрально («активность и расход энергии»).

### D-016. Программа «7 минут» исправляется; методика проверяется
Название «7 минут» не используется, пока реальная длительность не равна семи минутам. Корректный вариант считается по данным, длительность в тексте не пишется вручную.
Источник идеи (проверено по вторичным обзорам; саму статью автор плана не читал): Klika B., Jordan C. «High-intensity circuit training using body weight: maximum results with minimum investment», ACSM's Health & Fitness Journal, 2013, 17(3):8–13, doi 10.1249/FIT.0b013e31828cb1e8. Круг из 12 упражнений: 30 с работы, 10 с отдыха между упражнениями; в источниках боковая планка — по 15 с на сторону. Расчёт для 12 упражнений: 12×30 + 11×10 = 470 с = 7 мин 50 с.
Ограничения доказательной базы (по обзору LiveScience): протокол описан в статье и не проверялся на группе людей; критики сомневаются в эффекте и расходе энергии; авторы не рекомендуют его при избыточном весе, прошлых травмах, пожилом возрасте, при гипертонии и болезнях сердца. Эти ограничения ещё не подтверждены по первоисточнику, поэтому в `cautions` пока не вносятся.
Формулировка в приложении: «по мотивам», без утверждения, что это опубликованный протокол и без обещаний эффекта. Нужно добавить упражнения, которых нет в каталоге: подъём на стул, отжимания с поворотом, бег на месте, выпады с чередованием ног. Название программы — нейтральное («Круг: 12 упражнений»).

### D-017. Украинский — черновик до языковой проверки
Украинские тексты готовятся как черновик и помечаются `review: "draft"`. Публикация с украинским интерфейсом — только после проверки носителем. До этого `enabledLangs` для публичной версии остаётся `['ru']` (украинский включается флагом в тестовых сборках).

### D-018. Сопровождение изменений
Каждое изменение сопровождается тестами; схема хранилища меняется только миграциями, которые не удаляют данные пользователя (проверяются тестом на снимках старых данных); исходные материалы не удаляются без проверки зависимостей; PROJECT/STATUS/DECISIONS обновляются по мере этапов.

### D-019. Программа «Круг: 12 упражнений», 7:55
Название фиксировано: «Круг: 12 упражнений». Расчётная продолжительность — **7:55** (12 упражнений: 11×30 с + боковая планка 15+15 с = 360 с работы; 11×10 с отдыха между упражнениями = 110 с; 5 с на смену стороны в боковой планке; итого 475 с). Первоначальный расчёт 7:50 не учитывал паузу на смену стороны и заменён решением владельца. Название «7 минут» для этого комплекса не используется. Длительность в интерфейсе всегда считается движком по данным; тест сверяет её с 475 с.

### D-020. Ограничения формулировок и противопоказаний
- Противопоказания и ограничения (`cautions`) добавляются только с указанием первоисточника, который проверен. Для круга ограничения из обзоров не вносятся, пока не проверена статья Klika & Jordan (2013).
- В текстах нет обещаний похудения, определённого расхода калорий и гарантированного тренировочного эффекта. Валидатор данных ловит такие формулировки.

### D-022. Модель сторон и режимов в программах
- Поле `sides`: `none` (нет сторон), `sequential` (сначала все повторения/время на одной стороне, затем на другой; значение времени и повторений — **на каждую сторону**), `alternating` (стороны чередуются внутри одного блока; значение — на весь блок).
- Расчёт: `sequential` считает работу ×2. Сторона 1 — правая, сторона 2 — левая; порядок фиксирован и показывается на экране («Правая сторона», «Левая сторона»).
- Пауза на смену стороны: параметр `switchSec` на упражнение (по умолчанию 0 — только сигнал «смена стороны»). **Решение владельца: для боковой планки в круге `switchSec = 5`** (15 с правая сторона → 5 с смена положения → 15 с левая сторона). Итоговая длительность круга — 7:55 (475 с).
- Отдых между упражнениями не добавляется после последнего элемента программы; между сторонами одного упражнения вместо отдыха действует только `switchSec`.
- Элемент программы может задавать время для упражнения, которое в каталоге по умолчанию в повторениях (круг): это «подход на время», цель — максимум аккуратных повторений за заданное время, без счётчика повторений.
- Тесты движка обязаны проверять: общее время каждой программы, порядок сторон, пятисекундную паузу между сторонами боковой планки, отсутствие отдыха после последнего упражнения, `alternating` без удвоения времени, 475 с для круга. Подходы на время (без счётчика повторений) реализуются отдельным типом шага, а не флагом у подхода на повторения.

### D-025. Временная версия без сборки (предпросмотр) до миграции на React + TypeScript
Владелец (2026-11-13) просит как можно быстрее получить работающее приложение на GitHub Pages. Пока npm недоступен, создана версия на HTML, CSS и ванильных ES-модулях без сборки и без зависимостей. Это **промежуточный** этап: D-005 (React + TypeScript + Vite) не отменяется.
- Переносятся без переписывания логики (после перевода в TS): `engine`, `stats`, `catalog`, `data`, `i18n`, `store`, `format`, `dates`, данные `data/*`, `locales/*`, токены `css/tokens.css`, тесты на `node --test`.
- Переписываются на React: `js/screens/*`, `js/ui.js`, `js/router.js` (React Router по D-012), `js/main.js`, разметка `index.html`.
- Ограничения версии: шрифт системный (Manrope не подключён, D-023), украинского нет (D-017), service worker нет, сервера и оплаты нет, тексты и круг — черновик (`review: "draft"`).
- Публикация: `.github/workflows/pages.yml`; метка версии `?v=<sha>` проставляется `tools/stamp.sh`.

### D-026. Автономная поставка: один файл `standalone/index.html`
Владелец (2026-11-14) хочет обновлять приложение с Android через браузер GitHub, заменяя один файл. Решение: исходники (`index.html`, `css/`, `js/`, `data/`, `locales/`) остаются основой и не меняются; `node tools/bundle.mjs` собирает из них `standalone/index.html` (HTML + CSS + модули + JSON). Код модулей не переписывается: при запуске каждый модуль превращается в blob-URL, пути импортов подменяются, запросы к `data/*.json` и `locales/*.json` отдаются из встроенных данных. Тест `tests/standalone.test.mjs` проверяет, что встроенное совпадает с исходниками побайтно и что закоммиченный файл актуален. Пользовательские данные (ключи localStorage) не затронуты.
Единственный внешний адрес — SDK Telegram (`telegram.org`), он подгружается только внутри Telegram Mini App, как и раньше.

### D-033. Серверная архитектура Cloudflare, $0 (2026-11-18)

Объединение аккаунтов — только по одноразовому коду (10 мин), ничего не склеивается по имени/почте. Синхронизация: LWW для документов, история по id с надгробиями. ### D-035. Фото профиля как документ синхронизации (2026-11-20)
Пользователь выбирает фото из галереи, обрезает в круглом кадре (перетаскивание + масштаб), на устройстве сжимается до JPEG 256×256 (≈15–25 КБ) и хранится документом `avatar` = `{ img: "data:image/jpeg;base64,…" }` (пустая строка — фото убрано). Документ едет обычной синхронизацией (последняя правка побеждает), поэтому миграция D1 и новые маршруты не нужны, а при удалении аккаунта фото стирается каскадом. Сервер принимает только JPEG-data-URL ≤ 60 000 символов (SVG, ссылки и скрипты отклоняются). Приоритет показа: своё фото → фото Telegram (только показ) → буква. Если фото понадобится в крупном размере или для других пользователей — вынести в Cloudflare R2 (потребует отдельного решения: бесплатный лимит, привязка).
