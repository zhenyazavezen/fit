# План миграции ZAVEZEN_FIT на React + TypeScript + Vite

Статус: **на согласовании**. Код не менялся.

## 1. Модули основы: что с ними делаем

| Модуль (js/) | Новое место | Объём изменений | Что сохраняем | Что меняем |
|---|---|---|---|---|
| `config.js` | `src/config.ts` | почти без изменений | поля config, версия, префикс хранилища | типы; BUILD/версия из Vite (`define`), вместо чтения `meta[name=build]` и подстановки `sed` |
| `dates.js` | `src/lib/dates.ts` | почти без изменений | все функции (неделя с понедельника, месяцы) | только типы; добавляются тесты |
| `feedback.js` | `src/platform/feedback.ts` | почти без изменений | WebAudio-сигналы, разблокировка по жесту, вибрация, учёт настроек | типы |
| `tg.js` | `src/platform/telegram.ts` | малые | вся логика: ready/expand, цвета, viewport→`--app-h`, safe-area, haptic, BackButton, подтверждение закрытия, openLink | собственные минимальные типы WebApp (без пакета); геттер сырого `initData` (для будущего API; локально не доверяем); хук `useTelegramBackButton` |
| `store.js` | `src/storage/*` | средние | копия повреждённых данных `:corrupt:`, история без лимита, сигнал ошибки записи, write-hook, in-memory запасной вариант, миграции | типы записей; интерфейс `KeyValueStore`; репозитории (`history`, `favorites`, `programs`, `settings`, `activeSession`) получают `subscribe` для `useSyncExternalStore` и хуки `useHistory()` и т. п.; миграция схемы v2: `updatedAt`, признак удаления вместо физического (готовность к синхронизации) |
| `i18n.js` | `src/i18n/*` | средние | `t()` с `{var}`, множественные числа через Intl.PluralRules, откат на русский | загрузка не через `fetch`, а через динамический `import()` JSON (отдельный чанк на язык); `I18nProvider` + `useT()`; типизированные ключи из `ru.json`; украинский включается добавлением файла |
| `util.js` | `src/lib/*` + `src/ui/*` | разделяется | чистые функции: `fmtClock`, `clamp`, `normalize` (ё→е), `uid`, `debounce`, `reducedMotion` | DOM-помощники (`$`, `$$`, `append`, `h`, `icon`) заменяет React; `icon` → компонент `<Icon>`; `figure` (манекен) удаляется |
| `router.js` | `src/app/router.ts` + `RouterProvider.tsx` | основная переработка | вся семантика: без hash (занят `tgWebAppData`), `history.state`, стек обработчиков «Назад» (шторки/подтверждения), корни вкладок, синхронизация с BackButton, восстановление прокрутки | реализация под React: внешнее хранилище + `useSyncExternalStore`, хуки `useRoute()` и `useBackGuard()`, ленивые экраны (`React.lazy`) для быстрой загрузки; убирается лишний экспорт `$` |

Итого: **без изменений по логике** — config, dates, feedback; **малая адаптация** — tg; **средняя** — store, i18n, util; **переработка оболочки при сохранении логики** — router.

Порядок: тесты на старую логику пишутся вместе с переносом (даты, нормализация, plural, миграции, порча данных, стек «Назад»), чтобы перенос подтверждался, а не предполагался.

## 2. Дизайн-наработки
- Токены (цвета, радиусы, отступы, размеры) → `src/styles/tokens.css` без изменений.
- Tab bar, чипы, кнопки, карточки, шторки, недельная полоса из макетов → компоненты `src/ui/`.
- Главный экран перерабатывается: манекен и «сцена» убираются; героем становится типографика (рекомендованная тренировка, время, «Начать»). Макеты с манекеном остаются в `design/` как архив.
- Шрифт Manrope: хранить локально (P-4).

## 4. Файлы: сохраняем / переносим / создаём / не понадобятся

**Переносим (см. таблицу §1):** 8 модулей `js/*.js` → `src/**/*.ts`; `git mv` после базового коммита, чтобы история показывала перенос.

## 6. Организация тестов
- **Типы:** `tsc --noEmit` в строгом режиме.
- **Юнит (Vitest, Node):** движок тренировки на инжектируемых часах (старт, пауза/продолжение, пропуск, назад, подходы по сторонам, отдых, «ушёл в фон и вернулся» = скачок времени, восстановление из снимка, итог); статистика (недели/месяцы, серия, группировка); поиск и фильтры каталога (ё/е, алиасы, несколько категорий); i18n (plural, подстановки, откат на русский); хранилище (порча JSON → копия, ошибка квоты, миграция v1→v2, история не обрезается); даты; стек «Назад».
- **Компонентные (Vitest + jsdom):** шторка, фильтры каталога, элементы управления плеера.
- **Данные (`tools/validate.ts`):** уникальные id; ссылки `easier/harder` и элементы программ существуют; категории/мышцы/оборудование из `meta`; согласованность `mode` и `defaults`; наличие русского (и украинского) контента; **запрет медиа-полей**; предупреждения при отсутствии `review`; поиск обещающих формулировок («гарантирует», «сжигает жир», «лечит», «безопасно для всех» и т. п.).
- **Локализация (`check-i18n.ts`):** ключи ru и uk совпадают, плейсхолдеры одинаковы, формы множественного числа есть.
- **E2E (Playwright, Chromium):** 360×780, 390×844, 430×932. Сценарии: первый запуск; поиск и фильтры; карточка упражнения; запуск программы и прохождение до конца на ускоренных часах (`page.clock`) → запись в историю; перезагрузка посреди тренировки и продолжение; сворачивание (скачок часов + `visibilitychange`); эмуляция Telegram (заглушка `window.Telegram.WebApp`: BackButton, haptic, подтверждение закрытия, viewport); переключение языка; восстановление после повреждённого хранилища; **нет ошибок в консоли, нет неудачных запросов, нет запросов к видео и изображениям**; нет горизонтальной прокрутки; цели касания ≥ 44 px.
- **Бюджеты:** размер начального JS (gzip) проверяется скриптом; порог утвердим после первой сборки.
- **CI (GitHub Actions):** установка → типы → юнит → валидатор данных и i18n → сборка → e2e → публикация на Pages. Падение любого шага блокирует публикацию.

## 7. Готовность к Telegram Mini App API, серверу и Telegram Stars
| Будущая возможность | Что закладываем сейчас | Что НЕ делаем сейчас |
|---|---|---|
| Telegram Mini App API | весь доступ к `window.Telegram.WebApp` только через `platform/telegram.ts`; хуки для BackButton/MainButton | не используем `initData` для решений |
| Проверка initData и аккаунт | интерфейс `AuthService`; сейчас — локальный «анонимный» профиль + имя из Telegram для показа; заголовок API `Authorization: tma <initData>` описан в `services/api.ts` | нет сервера и входа |
| Серверное хранение | репозитории за интерфейсом; записи с `id`, `updatedAt`, признаком удаления; `store.setWriteHook` → будущая очередь отправки; правило конфликтов: история — только добавление, остальное — «последняя запись побеждает» | нет синхронизации |
| Бесплатный/платный доступ | в данных поле `access: "free" | "premium"`; интерфейс спрашивает `useAccess(id)` у `AccessService` (локально — всё бесплатно); платный контент позже отдаётся API (статический сайт публичен — «замок» на клиенте только вид) | нет оплаты |
| Telegram Stars | интерфейс `BillingService`: сервер создаёт ссылку счёта, клиент вызывает `openInvoice` и после закрытия **запрашивает доступ у сервера**, локально ничего не открывает | не реализуется |
| Окончание подписки | сервер возвращает срок доступа; клиент повторно запрашивает его при запуске | — |
| Адрес API | `VITE_API_URL`; нет значения → автономный режим | — |
Локальные реализации интерфейсов — рабочие (приложение полностью функционально автономно), а не заглушки.

## 8. Проверка черновых данных (40 упражнений, 9 программ)
Найдено при чтении `seed.mjs`:
1. **Опечатка** в алиасе `суперmen` (перезаписывается позже, но исправить в данных).
2. **Формулировки, похожие на медицинские/безопасностные утверждения** — убрать или смягчить: «без нагрузки на колени» (мост), «мягче для коленей, чем выпад вперёд» (выпады назад), «полезно при сидячей работе» (снежный ангел, растяжка груди), «помогает после долгого сидения» (сгибатели бедра), «Безопасное упражнение» (мёртвый жук), «расслабляющая» (поза ребёнка).
3. **Длительность в тексте** («примерно десять минут», «7 минут») — длительность считает движок по данным, в описаниях её быть не должно. Прежняя программа из 7 упражнений по 30 с выходила около 4,5 минут, название вводило в заблуждение (P-6).
4. **Семантика `perSide`** не определена: для повторений — «на каждую сторону», для времени — «секунд на сторону»; зафиксировать в типах и валидаторе.
5. **Уровни:** «Доброе утро» (good_morning) помечено начальным; наклон с нагрузкой на поясницу — переоценить в сторону «средний».
6. **Нет поля** для ограничений и источника: добавить `cautions?: [{text, source}]` — заполняется только при достоверном основании; пока пусто. Добавить `review: "draft"`.
7. **Цели:** нет «снижения веса» из ТЗ — формулировка без обещаний (P-7).
8. **Нет поля `access`** (для будущей подписки) — добавить `free` по умолчанию.
9. `equipment` как массив из одного значения — допустимо, но схема должна разрешать несколько (стул + стена).
10. Все описания пока на русском; украинские — черновик, проверка носителем (P-8).

## 10. Риски
- **Среда без доступа к npm** — блокирует сборку и тесты (STATUS, блокер 1).
- **Рост размера загрузки** из-за React — снижаем ленивой загрузкой экранов и языков, измеряем.
- **Контент без профессиональной проверки** — помечен `draft`, не выдаётся за методику.
- **Статический хостинг публичен** — платный контент потребует API.
