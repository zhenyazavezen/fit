# Тестирование: что реально запускалось

Дата: 2026-11-18. Запуск: `tools/test-all.sh` (Node 22, без npm).

## Выполнено (автоматически)
- `node tools/validate.mjs` — 61 упражнение, 17 программ, тексты, ссылки цепочек, запрещённые формулировки.
- Клиент (`tests/*.test.mjs`): движок таймеров, каталог и методика (баланс жим/тяга, гамстринг у новичков, FREE/PREMIUM), профиль и подбор (уровень, цель, инвентарь, ограничения, восстановление, возврат после перерыва, карта тела), доступ, сборка standalone.
- Сервер (`tests/worker/*.test.mjs`) на D1, эмулированной через `node:sqlite` (те же SQL и транзакции): проверка подписи Telegram (подделка, чужой токен, срок, будущее), Google ID token с **локально сгенерированными ключами** (aud, iss, exp, подпись, kid, alg, nonce), сессии (хэш в базе, выход, срок), лимиты, CORS, ошибки, удаление аккаунта, синхронизация (миграция, конфликты, надгробия, изоляция пользователей, валидация, квоты, постраничность), привязка/объединение (код, одноразовость, перебор, конфликт провайдеров, откат транзакции, Premium, отвязка).
- Сквозная проверка клиент↔сервер: реальный `js/sync.js` против реального Worker (миграция локальных данных, два «устройства», удаление, офлайн-очередь).
- Playwright (`tests/e2e/run.mjs`): 19 сценариев на автономной сборке.

## НЕ проверялось (нужны ваши ключи/действия)
- Реальная работа Worker и D1 в Cloudflare (деплой, миграция, секреты).
- Реальная подпись Telegram (нужен токен бота и запуск из Telegram) и реальный Google OAuth (нужен Client ID). Логика проверена только на тестовых ключах.
- Открытие Google-входа внутри Telegram WebView и перенос через внешний браузер.
- Установка PWA на Android, офлайн-режим service worker на реальном устройстве (код написан, в браузере с `file://` не активируется).
- Нагрузка и лимиты Free-тарифов.
- Платежи (не подключены).
